## 2. Audit Findings, Vulnerabilities & Implemented Fixes

### Finding 1: Hardcoded Path Filter in `peek` Command (`src/kernel/shell.rs`)
* **Vulnerability / Limitation:** The `peek` shell handler previously contained literal test path comparisons:
  ```rust
  if file == "/" || file == "/dir/file.txt" { ... }
  ```
  This hardcoded specific test strings rather than generically enforcing the single-level directory layout supported by the root inode table.
* **Resolution:** Replaced with generic path separator analysis:
  ```rust
  let clean = file.trim_start_matches(|c| c == '/' || c == '.');
  if clean.is_empty() || clean.contains('/') || clean.ends_with('/') {
      serial::print("Error: Invalid or unsupported file path '");
      serial::print(file);
      serial::println("'.");
      return;
  }
  ```
  Any nested subpath, root slash, or trailing separator is rejected generically without hardcoded strings.

### Finding 2: Hardcoded Capacity Annotations in Filesystem Status (`src/kernel/shell.rs`)
* **Vulnerability / Limitation:** Shell `show_df` printed hardcoded strings `" (300 MiB)"` and `" (273 MiB)"` regardless of the actual mounted volume size.
* **Resolution:** Replaced with dynamic arithmetic calculated from superblock block counts and block size:
  ```rust
  let total_mib = (st.total_blocks as u64 * 4096) / (1024 * 1024);
  let free_mib = (st.free_blocks as u64 * 4096) / (1024 * 1024);
  ```

### Finding 3: Hardcoded Verification Counts in `aegisdetect` (`src/kernel/shell.rs`)
* **Vulnerability / Limitation:** Shell `aegisdetect` printed a static string `"3 total, 3 trusted, 0 tampered/missing"`. If any file had failed verification or was absent, the shell would still falsely claim all 3 were trusted.
* **Resolution:** Updated `verify_storage()` to return `(verified_count, total_found)`. The shell prints the live, computed verification statistics directly.

### Finding 4: Hardcoded PCI Vendor & Device ID for AHCI (`src/kernel/storage.rs`)
* **Vulnerability / Limitation:** The AHCI SATA controller scan specifically matched Intel ICH9 (`0x8086:0x2922`). Controllers from AMD, VIA, VMware, or other SATA controller revisions would not be registered.
* **Resolution:** Replaced with standard PCI Class/Subclass scanning:
  ```rust
  crate::drivers::pci::for_each_device(|dev| {
      if dev.class_id == 0x01 && dev.subclass_id == 0x06 { // Mass Storage, SATA / AHCI
          ...
      }
  });
  ```

### Finding 5: Fallback Constants in Superblock Block Counts (`src/fs/purplefs_v3.rs`)
* **Vulnerability / Limitation:** `PurpleFsV3::mount` defaulted to `76800` total blocks and `total.saturating_sub(6800)` free blocks if sector count was small.
* **Resolution:** Extracted `sb_total` and `sb_free` directly from the 512-byte on-disk superblock at offsets `sb[24..28]` and `sb[28..32]`, with sector count calculation taking precedence when sector count is provided.

### Finding 6: Stub Shell `insmod` Implementation (`src/kernel/apdrv.rs`)
* **Vulnerability / Limitation:** The shell `insmod` command was a stub that simply printed a success message for module names starting with `"e1000"` without loading file data from the disk.
* **Resolution:** Wired `insmod` to look up the module file from the mounted disk via `storage::with_fs()`, read the `.apdrv` binary, and invoke `load_binary()`.

### Finding 7: Placeholder Digest Verification (`src/security/aegis_detect.rs`)
* **Vulnerability / Limitation:** `verify_storage()` computed a SHA-256 hash but only verified `digest != [0u8; 32]` rather than validating against cryptographic hashes.
* **Resolution:** Introduced `TRUSTED_MANIFEST` containing authentic SHA-256 digest entries for baseline system files (`welcome.txt`, `version.txt`, `motd`) covering both standard and 300M layout images.

## 4. Honest Technical Assessment: What to Add to the Kernel Next

The kernel now possesses robust foundations: a dual-bitmap physical memory manager, 4-level paging VMM, preemptive priority round-robin scheduler with SMP multicore support, unified GPT storage layer supporting ATA/AHCI/NVMe, a journaling filesystem (PurpleFS v2), and modular driver loading (APDRV v3).

To evolve from a monolithic kernel runtime into a full-fledged operating system, the following 5 technical milestones should be added next:

### 1. Per-Process Virtual Memory Isolation (User PML4 & CR3 Switching)
* **Current State:** All scheduler tasks currently execute within the shared kernel PML4 table (`0x1a1000`). While user pointer validation (`validate_user_ptr`) checks canonical boundaries and page permissions, tasks do not have private address spaces.
* **What to Add:**
  - Allocate a dedicated PML4 frame for each user task.
  - Clone higher-half kernel mappings (e.g. `0xFFFF_8000_0000_0000..0xFFFF_FFFF_FFFF_FFFF`) into every user PML4 so kernel interrupts/syscalls remain mapped.
  - Switch `%cr3` during `switch_context` whenever the target task has a private page table.
  - Implement `copy_on_write` (COW) and demand paging for user tasks.

### 2. Ring 3 Execution & User-Mode Transition (`sysretq` / `iretq`)
* **Current State:** SYSCALL and SYSRET MSRs (`STAR`, `LSTAR`, `SFMASK`, `KERNEL_GS_BASE`) are configured with dedicated per-CPU kernel syscall stacks, but user tasks are currently spawned as kernel threads in Ring 0.
* **What to Add:**
  - Add an `enter_user_mode(entry_point, user_stack_top)` assembly primitive using `iretq` with User Code Segment (`0x23`) and User Data Segment (`0x1B`).
  - Set up a per-CPU Task State Segment (TSS) with `RSP0` set to the kernel syscall/interrupt stack so Ring 3 interrupts switch securely to Ring 0.
  - Implement ELF64 user binary loader in `apexec.rs` to load `.elf` executables from PurpleFS into user address spaces.

### 3. Native TCP/IP Network Stack (Smoltcp or Pure Rust Layer)
* **Current State:** The `e1000` (Intel 82540EM) and `rtl8139` drivers initialize hardware DMA rings and read valid MAC addresses, but packets received in DMA buffers are discarded because there is no protocol stack.
* **What to Add:**
  - **Layer 2 (Data Link):** Ethernet frame parser & dynamic ARP table (resolving IPv4 addresses to MACs).
  - **Layer 3 (Network):** IPv4 packet framing, checksum validation, and ICMP echo responder (enabling `ping`).
  - **Layer 4 (Transport):** UDP state machine (for DNS/DHCP) and basic TCP transmission control blocks (TCBs).
  - **Shell Command:** Add `ping <ip>` and `curl <ip>` to test real networking under QEMU `-net user`.

### 4. Virtual File System (VFS) & Unified Mount Table
* **Current State:** `storage.rs` directly mounts a single PurpleFS partition found during boot. Multiple filesystems cannot be mounted concurrently.
* **What to Add:**
  - Implement a generic VFS inode trait (`read`, `write`, `lookup`, `readdir`, `create`).
  - Support a hierarchical mount table (e.g. `/` on PurpleFS, `/dev` on DevFS, `/proc` on ProcFS, `/tmp` on TmpFS).
  - Standardize file descriptors (`fd: usize`) in `Task` structures (supporting standard `0=stdin`, `1=stdout`, `2=stderr`).

### 5. Inter-Process Communication (IPC) Primitives
* **Current State:** Tasks can only communicate via shared kernel state under spinlocks.
* **What to Add:**
  - **Pipes:** Ring-buffered unidirectional byte streams with blocking read/write syscalls (`pipe()` / `SYS_READ` / `SYS_WRITE`).
  - **Signals / Events:** POSIX-style signals (`SIGINT`, `SIGKILL`, `SIGTERM`) or asynchronous event queues.
  - **Shared Memory:** Syscall to map a common physical frame into two different user PML4 address spaces (`SYS_SHM_MAP`).
